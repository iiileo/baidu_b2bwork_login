介绍

本服务提供「入队 → 单 worker 执行 Playwright 登录 → 必要时人工验证码/扫码 → 回写 cookie / 失败原因」的完整链路。

入口说明
/ui/Web 控制台（Basic）
/docs.html本文档（公开）
/health健康检查（公开）
/vnc/...noVNC 同源代理（Basic）
/v1/*业务 API（Bearer 或 Basic）

鉴权

HTTP Basic（控制台 / VNC）

环境变量 BASIC_AUTH_USER、BASIC_AUTH_PASSWORD 同时非空时启用。保护：

  • /ui/* 控制台静态页
  • /vnc/* VNC 代理（含 websocket）
  • 也可用于调用 /v1/*

启用 Basic 后，x11vnc 可无密码；请勿对外暴露 7900，统一走 /vnc。

Bearer Token（程序调用）

Authorization: Bearer <API_TOKEN>

API_TOKEN 来自环境变量，默认示例为 dev-token-change-me。

规则摘要

路径鉴权
/health、/docs.html、/v1/console/bootstrap公开
/ui、/vnc仅 Basic（启用时）
/v1/*（除 bootstrap）Bearer 或 Basic
WS /v1/logs?token= / Bearer 头 / Basic 头

登录流程

  1. POST /v1/sessions 入队，返回 id 与 queue_position。
  2. worker 认领任务，状态变为 running。
  3. 若需图片验证码 → waiting_captcha，客户端提交验证码。
  4. 若需安全扫码 → waiting_security，展示二维码等待扫码。
  5. 成功 → succeeded + result.cookies；失败 → failed + error。
  6. 若创建时带了 webhook_url，等待/终态会回调。

silent=true 时：一旦需要人工介入（验证码 / 扫码 / 滑块），立即失败并处理下一个任务。

会话 status 枚举

值类型说明
queued 进行中 活跃 已入队，等待 worker 认领。可按 priority / 创建时间排序。
running 进行中 活跃 正在执行自动登录（打开页面、填表、轮询结果）。
waiting_captcha 等待 活跃 需要人工图片验证码。见 challenge.type=captcha_image。用 POST .../captcha 提交。
waiting_security 等待 活跃 需要安全扫码。见 challenge.type=security_qr，使用 qr_content（不返回图片）。扫码成功后页面跳转，worker 自动继续。
succeeded 终态 终态 登录成功。result.cookies 有值；密码字段已清空。
failed 终态 终态 登录失败。error.code / error.message 说明原因。
cancelled 终态 终态 被取消，或同用户名新会话覆盖旧会话。

活跃状态：queued / running / waiting_captcha / waiting_security。终态：succeeded / failed / cancelled。

error.code 枚举

出现在 Session 的 error 字段，以及 webhook session.finished 的 error：

{ "code": "bad_credentials", "message": "用户名密码错误" }
code说明
bad_credentials用户名或密码错误
captcha_required静默模式：需要图片验证码，已跳过
security_required静默模式：需要安全扫码，已跳过
slider_required需要滑块验证（无法自动完成）
captcha_timeout验证码人工等待超时
security_timeout安全扫码等待超时
timeout整体登录超时
unknown_state页面状态无法判定
other_page_error页面可见错误文案（message 带详情）
cancelled取消 / 被新会话覆盖
login_error通用登录失败（含重试用尽）
browser_error浏览器会话不可用且重试用尽

challenge 结构

仅在 waiting_captcha / waiting_security 时有值；其它状态多为 null。

API 返回（GET session / GET challenge）

图片验证码（带图）：

{
  "type": "captcha_image",
  "qr_content": null,
  "expires_at": "2026-11-03T15:30:00Z",
  "image_base64": "data:image/png;base64,iVBOR..."
}

安全扫码（只返回内容，不返回图片）：

{
  "type": "security_qr",
  "qr_content": "https://wappass.baidu.com/...",
  "expires_at": "2026-11-03T15:30:00Z",
  "image_base64": null
}
字段类型说明
typestring见下方 type 枚举
qr_contentstring \| null安全扫码必用；验证码场景为 null
expires_atstringUTC ISO 时间，后缀 Z
image_base64string \| null仅 captcha_image 有值；security_qr 恒为 null

challenge.type 枚举

值对应 status说明
captcha_imagewaiting_captcha图片验证码；看 image_base64，用 POST captcha 提交
security_qrwaiting_security安全扫码；以 qr_content 为准，客户端自行生成二维码，不返回图片

Webhook 中的 challenge

{
  "type": "security_qr",
  "qr_content": "https://...",
  "expires_at": "2026-11-03T15:30:00Z",
  "image_available": false
}

image_available 仅在 captcha_image 时可能为 true。

POST /v1/sessions

创建登录任务，HTTP 202。同 username 会取消旧的未终态会话。

请求体

{
  "username": "acct",
  "password": "secret",
  "webhook_url": "https://example.com/hook",
  "priority": 1,
  "client_ref": "order-001",
  "silent": false
}
字段必填说明
username是非空
password是非空；终态后服务端清空存储
webhook_url否回调地址
priority否默认 1，≥1
client_ref否业务引用
silent否默认 false

响应

{
  "id": "a1b2c3...",
  "status": "queued",
  "queue_position": 1
}

GET /v1/sessions/{id}

查询完整 Session 对象。不存在返回 404。

GET /v1/sessions/{id}/challenge

仅在 waiting_* 且存在 challenge 时返回，否则 404。

{
  "session_id": "a1b2c3...",
  "status": "waiting_security",
  "challenge": {
    "type": "security_qr",
    "qr_content": "https://...",
    "expires_at": "2026-11-03T15:30:00Z",
    "image_base64": null
  }
}

POST /v1/sessions/{id}/captcha

仅当 status=waiting_captcha 时可提交，否则 409。

{ "code": "1234" }

成功返回更新后的 Session 对象；worker 会读取验证码并继续登录。

DELETE /v1/sessions/{id}

取消会话。queued 立即 cancelled；running/waiting 标记 cancel_requested，worker 尽快退出。

GET /v1/queue

{
  "queued": 2,
  "running": 1,
  "waiting": 1,
  "retrying": 0
}
字段说明
queued排队中
running执行中
waitingwaiting_captcha + waiting_security
retrying预留，当前恒为 0

GET /v1/console/bootstrap

公开接口，供控制台初始化：

{
  "basic_auth_required": true,
  "default_vnc_page_url": "/vnc/vnc.html?autoconnect=true&resize=scale&path=vnc/websockify",
  "api_token_optional": true
}

GET / PUT /v1/console/settings

读写 GUI 设置：VNC 页面 URL、默认 webhook、priority；兼容字段可写 VNC 密码文件（推荐走 Basic+/vnc，无需密码）。

WS /v1/logs

实时日志文本流。鉴权：

  • ws://host/v1/logs?token=API_TOKEN
  • 或同源 Basic（浏览器自动带）

VNC 代理 /vnc

将容器内 http://127.0.0.1:7900 代理到本服务路径，需 Basic。

/vnc/vnc.html?autoconnect=true&resize=scale&path=vnc/websockify

iframe 与控制台同源，浏览器 Basic 登录一次即可同时访问控制台与 VNC。

Webhook 事件

创建会话时传入 webhook_url 后，服务端 POST JSON，并用 WEBHOOK_SECRET 签名（见实现头字段）。

type 枚举

type时机要点
session.waiting_captcha进入验证码等待带精简 challenge
session.waiting_security进入扫码等待带精简 challenge
session.finished终态status=succeeded/failed/cancelled；含 result/error

签名头

头说明
X-TimestampUnix 秒级时间戳
X-Signaturesha256= + HMAC-SHA256(WEBHOOK_SECRET, "{timestamp}.{body}")
Content-Typeapplication/json

finished 示例

{
  "id": "evt_...",
  "type": "session.finished",
  "session_id": "a1b2c3...",
  "status": "succeeded",
  "username": "acct",
  "client_ref": "order-001",
  "result": { "cookies": [ { "name": "...", "value": "...", "domain": "..." } ] },
  "error": null
}

curl 示例

# 创建（静默）
curl -sS -X POST "$HOST/v1/sessions" \
  -H "Authorization: Bearer $API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"username":"u","password":"p","silent":true,"client_ref":"t1"}'

# 查询
curl -sS "$HOST/v1/sessions/$ID" -H "Authorization: Bearer $API_TOKEN"

# 提交验证码
curl -sS -X POST "$HOST/v1/sessions/$ID/captcha" \
  -H "Authorization: Bearer $API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"code":"1234"}'

# 队列（Basic）
curl -sS -u "admin:admin" "$HOST/v1/queue"

# 取消
curl -sS -X DELETE "$HOST/v1/sessions/$ID" -H "Authorization: Bearer $API_TOKEN"

数据保留

  • 失败/成功/取消都会以终态留在 SQLite，不会立刻删除。
  • worker 启动时按 SESSION_TTL_DAYS（默认 7）清理过期终态记录。
  • 终态时清除 password；挑战图片文件会删除。
